# 手動注文メイン運用 設計メモ

## 1. 背景

kabuステーションを毎営業日確実に起動し、ログイン状態と API 接続を維持する運用は、個人の日次運用では負荷が高い。
そのため、KabuSys の主ルートを「自動発注」から「前日夜・当日朝の手動注文支援」へ移す。

自動発注機能は残すが、当面の本番運用では優先しない。KabuSys は売買候補、数量、理由、売却候補、記録、評価を担当し、実際の注文はユーザーが証券画面で手動実行する。

## 2. 運用方針

- 前日夜に翌営業日の BUY / SELL 候補を作る。
- 当日朝にギャップ、直近価格、見送り条件を確認する。
- ユーザーが証券画面で手動注文する。
- 約定後、ユーザーが約定データを KabuSys に投入する。
- KabuSys は投入済みポジションに対して、自動売買と同じ SELL 判断、保有評価、リスク監視、レポートを行う。
- KabuSys は発注しない。助言と記録に徹する。

## 3. 日次フロー

### 前日夜

1. `data_update`
2. `feature_gen`
3. `strategy_signal`
4. `portfolio_construction`
5. 手動注文候補レポート生成

前日夜レポートには以下を出す。

- 翌営業日の BUY 候補
- SELL 候補
- 推奨数量
- 前日終値ベースの想定金額
- シグナル理由
- 見送り条件
- 手動注文メモ欄

### 当日朝

1. データ鮮度と停止フラグを確認する。
2. 前日夜候補を再表示する。
3. 寄り前または寄り付き後の判断材料を確認する。
4. ユーザーが注文する銘柄を選ぶ。
5. 証券画面で手動注文する。

当日朝レポートには以下を出す。

- 今日注文すべき候補
- 前日終値からのギャップ注意
- 上限金額、想定利用率、1銘柄上限
- 見送り候補
- 売却候補

### 注文後

約定した注文を KabuSys に入力する。

```powershell
python -m kabusys.manual_trades add --date 2026-09-17 --code 72030 --side buy --qty 100 --price 3016 --apply
python -m kabusys.manual_trades wizard
```

GUI 入力は後続で Streamlit に追加する。GUI も CLI と同じ `manual_trades` テーブルへ登録する。

### 引け後

1. 手動投入済み約定をもとにポジションを評価する。
2. SELL 条件に該当する銘柄を翌営業日の売却候補として出す。
3. 日次損益、保有日数、売却理由を保存する。

## 4. データ設計

手動約定は、自動注文の `orders` と混同しないよう、専用の記録層を持つ。

候補テーブル:

- `manual_trades`
- `manual_positions`
- `manual_action_queue`

最低限の列:

| 列 | 内容 |
| -- | ---- |
| `trade_id` | 冪等キー |
| `code` | 銘柄コード |
| `side` | `buy` / `sell` |
| `qty` | 約定数量 |
| `price` | 約定単価 |
| `trade_date` | 約定日 |
| `source_signal_id` | 対応する Signal Queue ID（任意） |
| `note` | 任意メモ |
| `created_at` | 入力日時 |

`manual_action_queue` は発注キューではなく、ユーザーに提示する行動候補とする。

| 列 | 内容 |
| -- | ---- |
| `action_id` | 候補ID |
| `date` | 対象日 |
| `code` | 銘柄コード |
| `action` | `buy_candidate` / `sell_candidate` / `hold` / `skip` |
| `suggested_qty` | 推奨数量 |
| `reason` | 判断理由 |
| `status` | `open` / `done` / `skipped` |

## 5. 既存機能との関係

`signals` と `signal_queue` は引き続き候補生成に使う。ただし、手動注文メイン運用では `signal_queue` を自動発注キューとしてではなく、注文候補の中間成果物として扱う。

Execution Engine は当面、Paper / 検証用のまま維持する。本番運用の主導線には置かない。

## 6. 安全設計

- 手動注文メイン運用では、自動発注プロセスを起動しない。
- `manual_action_queue` は Execution Engine の対象外にする。
- ユーザーが明示的に自動発注へ戻すまで、kabuステーション API 接続を前提にしない。
- 手動約定取り込みは冪等にする。
- 同一銘柄を複数回買った場合は、まずは平均単価・合算数量で扱う。
- ロット別管理は後続課題とする。

## 7. 実装順

1. 手動注文メインのWebManualを追加する。
2. 前日夜・当日朝の候補レポートを整備する。
3. `manual_trades` 入力 CLI を追加する。
4. 手動ポジション評価レポートを追加する。
5. SELL 候補助言を自動売買ロジックから再利用する。
6. 週次・月次の手動運用成績レポートを追加する。

## 8. 完了条件

- kabuステーションを起動しなくても、翌営業日の売買候補を確認できる。
- ユーザーが手動注文した約定を KabuSys に投入できる。
- 投入済みポジションが SELL 判断と日次評価に含まれる。
- 自動発注なしで、1週間の手動注文運用を回せる。
