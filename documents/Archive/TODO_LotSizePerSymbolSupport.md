# TODO: Lot Size Per Symbol Support

> **Status: 完了 — Issue #291 / PR #293 にて実装済み（2026-05-11）**

## Background

発注数量計算は現状 `lot_size=100` を前提に丸めている。

対象実装:

- `src/kabusys/portfolio/position_sizing.py`

## Problem

現在は全銘柄一律で `100 株単位` として数量を切り下げている。

そのため、将来的に売買単位が異なる銘柄を対象ユニバースに含めると、

- 数量計算が実際の売買単位と一致しない
- 本来買える数量が 0 扱いになる
- 発注時に単位不整合が起きる

## Current Assumption

現時点の対象ユニバースでは `100 株単位` 前提で大きな問題が出ない可能性はある。

ただし、これは実装上の固定値依存であり、銘柄マスタを活用する拡張余地が残っている。

## 実装内容（Issue #291）

- `calc_position_sizes` に `lot_map: dict[str, int] | None = None` パラメータを追加
- `_lot(code)` ヘルパーで `lot_map` の銘柄別値を参照し、未指定銘柄は `lot_size` にフォールバック
- aggregate cap のスケールダウン処理でも `_lot(code)` を統一適用
- テストケース:
  - 100 株単位の通常銘柄（`lot_map` なし）
  - 100 以外の単位を持つ銘柄（`lot_map` あり）
  - 単元未満になって 0 株へ切り下がるケース
  - `lot_map` 未指定銘柄は `lot_size` フォールバック動作確認

## 設計上の決定事項

- `lot_map` は呼び出し元（ポートフォリオ構築エンジン）から渡す設計
- `stocks` テーブル / 銘柄マスタからの自動取得は将来課題
- `lot_size` デフォルト（100）は既存テストとの互換維持
