## 3. LINE通知 実装・機能要件（TODO）

ここから、KabuSysにおける具体的なLINE通知の設計と実装要件を定義する。
通知コンポーネント（例: `src/kabusys/operations/notifier.py`）を実装し、各フェーズから呼び出せるようにする。

### 3.1 通常運用（定期レポート）

- [ ] **Daily通知（日次）**
  - **送信タイミング**:
    1. 毎朝（8:30頃）: Executionモジュール起動完了時
    2. 毎夜（21:30頃）: 夜間バッチ完了時
  - **朝の内容**:
    - Kabuステーションとの接続正常確認。
    - 本日の発注予定シグナル数・予定投下金額のサマリ。
  - **夜の内容**:
    - 当日の取引結果サマリ（実現損益・約定件数等）。
    - 夜間バッチ（データ取得・特徴量生成・AI分析・シグナル生成）の正常完了報告。
    - 翌営業日のシグナル有無。

- [ ] **Weekly通知（週次）**
  - **送信タイミング**: 毎週金曜日の夜間バッチ完了後（または土曜朝）
  - **内容**:
    - 今週の実績サマリ（週間トータル損益、勝率、勝ち/負け銘柄上位）。
    - 現在保有中のポートフォリオ構成グラフやサマリ。
    - 累計の口座資産推移と現在値。

- [ ] **Monthly通知（月次）**
  - **送信タイミング**: 月末営業日の夜間
  - **内容**:
    - 月間の運用パフォーマンス詳細（トータルリターン、CAGR換算）。
    - 今月の最大ドローダウン（Max Drawdown）の確認。
    - マクロ相場レジームの推移振り返りと来月への持ち越し方針。運用継続または戦略見直しの判断材料を提供する。

### 3.2 障害運用（異常検知・アラート即時通知）

- [ ] **起動確認ができない**
  - **送信タイミング**: 朝のPre-Market確認時（8:00〜8:30付近）
  - **検知条件**:
    - Windows PCがオフライン、スリープ状態で応答がない。
    - Kabuステーションが起動していない、あるいはログインされていない。
    - APIトークンの取得に失敗（APIパスワード間違い、期限切れ等）。
  - **内容**:
    - 「【CRITICAL】Kabuステーションとの接続・起動に失敗しました。手動でPC・ログイン状況を確認してください。本日の自動運用は一時停止状態です。」

- [ ] **監視時の障害（ザラ場）**
  - **送信タイミング**: 前場・後場の稼働中（9:00〜15:00）に異常検知した即時
  - **検知条件**:
    - KabuステーションAPIの接続ロスト（タイムアウト頻発）。
    - 注文エラー（残高不足、規制銘柄等）の連続発火。
    - 想定外のポジション不整合、または部分約定放置による不適合。
    - 相場の急落による Kill Switch（最大ドローダウン超過）の発動。
  - **内容**:
    - 「【ERROR/KILL_SWITCH】ザラ場中の異常を検知しました。システムは発注を停止または防衛モードに入りました。[異常の詳細ログ]を確認してください。」

- [ ] **バッチのエラー（夜間・メンテナンス）**
  - **送信タイミング**: 夜間バッチ実行中（15:30〜21:30）にジョブがアボートした即時
  - **検知条件**:
    - J-Quants APIからの市場データ・財務データ取得失敗（リトライオーバー）。
    - DuckDB への書き込み制約違反・ファイル破損疑いエラー。
    - AIスコア推論プログラムの例外終了。
  - **内容**:
    - 「【BATCH ERROR】夜間バッチ[ジョブ名]が異常終了しました。翌営業日のシグナル生成に影響が出るため、明朝までに手動での再実行またはリカバリが必要です。」
