# Phase 1 バックテスト戦略

- 対象: KabuSys Phase 1（初期投資100万円）の戦略検証
- 作成: 2026-05-19

---

## 1. 背景・目的

### 1.1 Phase 1 の位置づけ

KabuSys は初期投資 100万円 から段階的に運用資産を拡大していく方針をとる。
Phase 1 では「生き残ること」を最優先とし、大きなドローダウンで退場しないことを目標とする。

| フェーズ | 資産規模  | 優先目標                       |
| -------- | --------- | ------------------------------ |
| Phase 1  | 〜100万円 | 生存・学習。ドローダウン最小化 |
| Phase 2  | 〜500万円 | 安定成長。Sharpe > 1.0         |
| Phase 3  | 500万円〜 | リターン最大化                 |

### 1.2 検証の動機

アブレーション分析（2023〜2025年）の結果、現行設定が年によって大きく成績が変動することが判明した。
2017年からのデータが利用可能になったことで、複数の相場局面にまたがる統計的に信頼できる検証が可能になった。

### 2.3 知見

**モメンタム因子**

- 2024〜2025の上昇相場で不可欠。除外すると2024年が-15.2%に悪化
- 下落局面での寄与が限定的なため、相場方向依存が強い

**ボラティリティ因子**

- 2023〜2024は除外すると改善（no_volatility が大幅アウトパフォーム）
- 2025は除外すると-7.5%に悪化
- **局面によって寄与が反転する** → 固定ウェイトでは対応困難

**ニュース因子**

- 除外しても平均 CAGR が base を上回る（+16.6% vs +13.2%）
- 2024年でニュース因子が帰属損失を生んでいる可能性

**重要な示唆**
すべての相場局面に強いパラメータを探すことは構造的に困難。
機関投資家と同様に、**リスク管理（ポジション縮小・損失ストッパー）で資本を守りながら**、
上昇局面での機会を取りに行く設計が合理的。

## 3. Phase 1 保守的設定の根拠

### 3.1 現行設定の問題点

- 最大4ポジション × 投下資金80% = 1ポジションに最大20%集中
- 100万円では1銘柄で最大20万円。損切り9%で-18,000円 / トレード
- ドローダウン発生時にポジション全体が危機にさらされる

### 3.2 Phase 1 保守的設定

| パラメータ       | 現行 (ベースライン) | Phase 1 保守 | 変更理由               |
| ---------------- | ------------------- | ------------ | ---------------------- |
| 最大ポジション数 | 4                   | 3            | 1銘柄あたりリスク分散  |
| 最大投下資金比率 | 0.80                | 0.50         | キャッシュバッファ確保 |
| DD ストップ      | なし                | 12%          | クラッシュ時の強制防御 |
| DD タイムアウト  | なし                | 30日         | 回復後に自動再稼働     |
| TOPIX ベアガード | ON (0.5/0.0)        | ON (0.5/0.0) | 維持                   |
| その他           | 同上                | 同上         | 維持                   |

### 3.3 段階的な保護追加の考え方

```
A1（ベースライン）
  └── ポジション縮小・投下率引下げ → A2（保守）
        └── DDストップ追加 → A3
              └── ベアガード追加 → A4（フル保護）
```

各ステップの効果をバックテストで定量化することで、
どの保護機能がリターン・ドローダウムに寄与するかを分離して評価する。

## 6. 採択基準

9年間データを用いるため、3年間より厳格な基準を設定する。

| 指標          | 採択基準  | 根拠                             |
| ------------- | --------- | -------------------------------- |
| 9年間 CAGR    | > 5%      | 個人投資家のインデックス超過水準 |
| 9年間 Sharpe  | > 0.5     | リスク調整後で意味のある水準     |
| Max Drawdown  | < 25%     | 100万円で心理的に継続可能な上限  |
| 利益年数      | ≥ 6 / 9年 | 3分の2以上は勝てる               |
| 最悪年 CAGR   | > -20%    | 単年壊滅を防ぐ                   |
| Profit Factor | > 1.1     | 基本的な正の期待値               |

## 9. 結果分析の観点

### 9.1 Group A の読み方

```
A1 → A2: ポジション縮小・利用率引下げだけで Max Drawdown が改善するか
A2 → A3: DDストップが下落耐性にどれだけ寄与するか
A3 → A4: ベアガードがSharpeを改善するか（CAGR とのトレードオフ確認）
A4 vs A1: Phase 1 フル構成が9年間通算でベースラインを上回るか
```

### 9.2 Group B の読み方

各クラッシュ年について:

```
baseline_MDD - full_MDD = 保護機能の実効ドローダウン削減量
```

2020年（COVID）で削減量が大きいならDDストップが機能している証拠。

### 9.3 Group C の読み方

DD stop 閾値と CAGR・MDD のトレードオフ曲線を確認:

- 厳しすぎる（8%）: Sharpe が低下 → キャッシュドラッグが大きい
- 緩すぎる（20%）: MDD が none とほぼ同じ → 保護が機能していない
- 最適点: CAGR 低下が小さく MDD が十分に抑制されている閾値

### 9.4 Group D の読み方

- 3年以上マイナス: 戦略自体の見直しが必要
- クラッシュ年のみマイナス（2018/2020/2022）: DDストップ/ベアガード調整で対処可能
- 一貫してプラス: Phase 2 移行の判断材料

## 12. 分析結果・採択判断（2026-05-19）

### 12.1 総合評価

**A4（Phase 1 フル設定）は採択基準を全項目で未達。** 主な要因は Bear Guard の過剰フィルタリング。

### 12.2 重要な発見

**発見 1: Bear Guard (Layer 2 / TOPIX MA クロス) が最大の足を引っ張っている**

```
BG ON (A1/A4): CAGR ≈ -3.6〜-3.8%、トレード数 350〜483件
BG OFF (A2/A3): CAGR ≈ +8.9〜+9.1%、トレード数 1,000〜1,014件
```

BG ON でトレード数が約 65% 減。2017〜2025 の TOPIX は概ね上昇基調で、MA クロスによるベア判定が過剰に発火し強気局面の機会を大量に排除した結果。

**発見 2: DD Stop は Max DD 削減に有効（CAGR への影響は軽微）**

**発見 3: Group C — DD Stop 閾値の感度は Bear Guard ON 下では無意味**

全シナリオが Bear Guard ON で CAGR マイナス。根本問題が Bear Guard にある間、閾値チューニングは効果なし。

**発見 4: クラッシュ耐性は局面依存**

- 2020（COVID）: BG ON で MDD が 54.9% → 37.0%（**-18pt** 削減）。Bear Guard が機能。
- 2018・2022: BG ON の方が CAGR が悪化。回復局面でも取引を抑制し続けていた。

## 15. 分析結果・採択判断（2026-05-20）

### 15.1 発見 1: strong_bear=0.0（強ベア完全停止）が CAGR 毀損の主因（Group E）

weak_bear を緩和しても効果はほぼゼロ（E1 vs E3 が同等）。**strong_bear を 0.0→0.25 に変えるだけで CAGR が約 +4pt 回復**する（E1 → E2）。ただし BG を完全 OFF（E8 = A3）にしても Max DD 40.3%、Sharpe 0.344 に留まり、採択基準を達成できない。

```
strong_bear の緩和効果（weak_bear=1.0 固定）:
  strong_bear=0.00 → CAGR -3.34%, 取引数 428
  strong_bear=0.25 → CAGR +1.49%, 取引数 603  (+4.8pt)
  strong_bear=0.50 → CAGR +5.74%, 取引数 778  (+4.2pt)
  strong_bear=1.00 → CAGR +9.05%, 取引数 1014 (+3.3pt)
```

### 15.2 発見 2: 2017年の損失は Bear Guard ではなく threshold が主因（Group F）

**F1（BG ON）と F2（BG OFF）の CAGR が完全一致（-20.4%）**。BG は 2017年の損失に無関係。真の原因は threshold=0.58 が 2017年の市場特性に合わず、低精度シグナルを大量発生させていたこと。

```
threshold の効果（2017年単年、BG OFF 固定）:
  threshold=0.58 → CAGR -20.4%, Max DD 24.5%, 取引数 102
  threshold=0.60 → CAGR -20.2%, Max DD 23.7%, 取引数 90  （ほぼ変化なし）
  threshold=0.62 → CAGR  -4.5%, Max DD 11.4%, 取引数 75  （劇的改善）
  threshold=0.65 → CAGR  -0.4%, Max DD  9.9%, 取引数 36  （ほぼ損益均衡）
```

F7（stop_loss=7%）・F8（stop_loss=6%）は F2（9%）と完全一致。2017年では ATR トレーリングストップが先に発動しており、固定 stop_loss 閾値（6〜9%）は機能していない。

### 15.3 発見 3: DD Stop の厳格化（8%・10%）は逆効果（Group G）

```
DD Stop の効果（util=50%, threshold=0.58, BG OFF 固定）:
  DD stop= 8% → CAGR -2.99%, Max DD 51.9%  ← 最悪（頻発→回復局面を逃す）
  DD stop=10% → CAGR +9.60%, Max DD 52.6%
  DD stop=12% → CAGR +9.05%, Max DD 40.3%  ← A3 参照
```

DD stop の厳格化は Max DD 削減に寄与しない。G7（stop_loss=7%）も G1 と完全一致のため、stop_loss 変更は 9 年通算でも無効。

### 15.4 発見 4: 利用率 30% が Max DD 抑制の最有力手段（Group G）

G3（util=30%）のみ **Max DD 26.2%（採択基準 25% まで 1.2pt 差）** を達成しながら CAGR +7.74%、PF 1.320 を維持。利用率の引下げが最もコスト低く Max DD を削減できる手段。

## 16. Bear Guard 代替アプローチ / 次ステップ — Group H 実行計画（銘柄単位 MA200 フィルター）

### 16.1 背景

現行の TOPIX MA クロスベアガード（Layer 2）は **市場全体に一律適用** するため、
指数が弱くても個別銘柄が強い局面（セクターローテーション等）でも BUY を全停止してしまう。

**Group E・F・G の検証（2026-05-20）で TOPIX BG 閾値の最適化だけでは採択基準に届かないことが確認された。**
Bear Guard の粒度を **「指数単位→銘柄単位」** に変更し、
強い銘柄は引き続き買いながら弱い銘柄のみを排除する設計に移行する。

### 16.2 銘柄単位 MA フィルターの段階的アプローチ

```
Step 1: Group E/F/G 結果を確認 ← 完了（2026-05-20）
  └─ TOPIX BG 閾値の最適化では採択基準に届かないことを確認 → Step 2 へ

Step 2: use_ma200_filter=True による Group H バックテスト（コード変更ゼロ）← 現在のステップ
  ├─ features テーブルに ma200_dev（終値/MA200 - 1）が銘柄ごとに保存済み
  ├─ signal_generator.py に use_ma200_filter フラグが既実装
  ├─ TOPIX BG を OFF にし、銘柄単位 MA200 フィルターに置き換えて検証
  └─ 採択基準達成 → Step 2 設定を採用 / 不十分 → Step 3 へ

Step 3: 銘柄ごとの MA25/MA75 クロスを features に追加（実装コスト大）
  ├─ features テーブルに ma25_dev, ma75_dev を追加（スキーマ変更）
  ├─ feature_engineering.py のパイプラインで銘柄ごと MA25/MA75 を計算
  ├─ signal_generator.py に銘柄 MA クロス判定フィルターを実装
  └─ Group I でバックテスト検証
```

### 16.3 Group H — 銘柄単位 MA200 フィルター検証（Step 2）

**目的**: TOPIX 指数ベアガードを廃止し、銘柄ごとの MA200 フィルターに置き換えた場合の
9年通算パフォーマンスを定量化する。Group G（util=30% が Max DD 最近接）および
Group F（threshold=0.62 が 2017年問題を解消）の知見を組み込む。

**前提知識**:

- `ma200_dev` は `features` テーブルに既存（銘柄ごとの終値/MA200 - 1）
- `use_ma200_filter=True` で MA200 を下回る銘柄の BUY を抑制（バイナリフィルター）
- 追加実装不要。stop_loss 変更は Group F・G で無効と判明のため 9% 固定

固定設定: max_pos=3, TOPIX BG=OFF, DD stop=12%, stop_loss=9%, 期間 2017〜2025

| シナリオ              | util    | threshold | ma200_filter | 狙い                                        |
| --------------------- | ------- | --------- | ------------ | ------------------------------------------- |
| H1_a3_ref             | 50%     | 0.58      | False        | A3 参照（= G1。MA200 なし）                 |
| H2_ma200_only         | 50%     | 0.58      | **True**     | MA200 フィルター単体の寄与                  |
| H3_util30_ma200       | **30%** | 0.58      | True         | G3（util=30%、Max DD 26.2%）に MA200 を加算 |
| H4_thr62_ma200        | 50%     | **0.62**  | True         | threshold=0.62（2017年問題修正）+ MA200     |
| H5_util30_thr62_ma200 | **30%** | **0.62**  | True         | G3 + F5 の知見を組み込んだ最有力複合設定    |

**読み方**:

- H1 → H2: MA200 フィルター単体の効果（CAGR/MDD トレードオフ）
- H2 → H3: util=30% との相乗効果（Max DD を採択基準 25% 以下に押し込めるか）
- H2 → H4: threshold=0.62 の 9年通算効果（2017年改善 vs 他年トレード数減少のトレードオフ）
- H5: CAGR>5% かつ Max DD<25% の **同時達成を狙う最重要シナリオ**

**採択判断ロジック**:

```
H5 が採択基準を満たす → H5 設定を Phase 1 採用。Group I は不要
H5 が未達（CAGR または Max DD）→ Group I（銘柄 MA25/75 クロス実装）へ進む
H2 で CAGR が大幅低下（< 5%）→ MA200 単体フィルターは効果薄。Group I へスキップ
```

> **注意**: 2020 年（COVID 急落）は全銘柄が同時に MA200 を割り込むため、
> 銘柄単位フィルターも **システミックリスクには有効でない**。

### 22.2 Sharpe 改善の仮説

**② 分母を下げる（リターンのブレを小さくする）**: 損失を早く確定し、含み損長期保有を防ぐ

現在の設定（max_holding_days=60、trailing_stop_atr=2.0）は保有期間が長く、含み損がドローダウンに乗り続けるリスクがある。**保有日数短縮・ATR 縮小がリターンのブレを抑制しSharpe を改善する最有力仮説。**

## 24. 分析結果・採択判断（Group J）（2026-05-23）

### 24.1 J2（hold45）= J1（変化なし）

avg_holding_days が 13.9d のため、上限を 60→45日に短縮しても実質的な影響ゼロ。現行設定では保有上限が有効に機能していない。

### 24.2 J4 = J6（ATR 1.5 単体と複合が同一）

J4（ATR1.5）の avg_holding_days は 11.6d で 45日上限に全く届いていないため、hold45 の追加効果ゼロ。ATR 締め単体の結果と完全一致。

### 24.3 保有日数短縮（J3）：CAGR が崩壊

30日上限で取引数が 697→449件（-36%）、CAGR が +7.72% → +1.21% に急落。30日超えの保有が利益の主要な源泉になっていることを示す。Max DD は 23.44% まで改善するが CAGR・PF ともに採択基準未達。

### 24.4 ATR 係数縮小（J4/J5）：Sharpe は改善しない

- **J4（ATR1.5）**: Max DD が 24.96% → 23.46% に小幅改善。ただし CAGR -1.3pt・Sharpe -0.040 の犠牲。Sharpe 改善に寄与しない。
- **J5（ATR1.2）**: さらに絞るとトレーリングストップがノイズで多発し、Max DD が **36.78% に悪化**。ATR を過剰に締めると逆効果。

### 24.5 閾値引き上げ（J7/J8）：Max DD が崩壊

- **J7（thr=0.59）**: Max DD 47.98%（基準の約 2 倍）。閾値変更で取引数が増えたが、質が下がり損失が拡大。
- **J8（thr=0.60）**: CAGR は最高（+8.80%）だが Max DD **72.82%** — 100万円で 72万円の含み損。実用不可。

### 24.6 Group J の総括と採択決定

**目標（Sharpe > 0.5）を達成するシナリオは存在しない。** どのパラメータ調整も Sharpe を 0.382 から向上させられなかった。
