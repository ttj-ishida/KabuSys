# TODO: 低コスト前提の市場データ・ニュース情報源構成

- 目的: 月額コストを抑えつつ、KabuSys の研究・バックテスト・実運用に必要な情報を、用途別に適切な情報源へ分担する
- 前提:
  - 市場・財務・銘柄マスタの基盤は `J-Quants` を継続利用する
  - 発注・口座余力・保有残高・最新値動きは `kabuステーション API` を利用する
  - ニュースは `Yahoo News` 単独ではなく、`適時開示(TDnet)` と `EDINET` を中核に再設計する
  - `会社四季報オンライン` は自動収集基盤ではなく、人間の調査補助として扱う

## 4. 設計上の判断メモ

- `J-Quants` は研究・バックテスト・日次特徴量の主軸として適切
- `kabuステーション API` は執行と口座状態の唯一の正として維持すべき
- `適時開示` は「後から人が見る情報」ではなく、「先に全件保存してイベントDB化する情報」として扱うべき
- `Yahoo News` は速報補助として使えるが、シグナル主役には向かない
- `会社四季報オンライン` は自動収集基盤よりも、人手運用の補助UIとして価値が高い
- `TDnet API` は将来拡張候補であり、初期フェーズでは費用対効果が悪い
